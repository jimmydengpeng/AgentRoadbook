# LLM 基础概念

大语言模型接收你写进请求的文本，再生成一段新的文本。后面的章节都从这三个词出发：模型、提示词、补全。

## 知识点概述

模型在这里指聊天模型，也就是根据已有文本继续生成内容的组件。它不读取你的仓库，也看不到没有放进本次请求的变量。你希望它知道的事实、规则和问题，都要写进这次发送的内容。

提示词是这次交给模型的指令和材料。它可以是一句话，也可以是好几条消息。补全是模型新生成的那段文本。聊天界面里，补全通常就是助手的回复。

一次聊天调用常用一份消息列表，而不是一整段分不清身份的字符串。常见角色有三类：开发者或系统写的指令、用户说的话、助手已经说过的话。具体角色名以你接入的接口为准。同一家服务商也可能提供两种请求形状，例如把材料放进 `input`，或放进 `messages`。

生成不是查表。同一份提示词再次发送，文字可以不同。因此后面写 Agent 时，不能假定模型某一次的原话永远复现，要把能检查的部分留给程序。

## 核心原理

可以把一次调用看成映射：消息进去，新文本出来。映射的规则在模型参数里，你能控制的是这次送进去的内容，以及你如何对待送出来的文本。

消息列表让程序分得清「规则」和「用户刚说的话」。有的接口还会让开发者消息优先于用户消息。这只说明模型读指令时的优先顺序，不是访问控制。密钥、数据库和本地文件的权限仍在你的程序里。

模型输出的用途由你决定。展示给用户，是聊天。要求它按某种格式写，是后面的提示词和结构化输出。让它提议下一步动作、再由程序执行，才进入本站说的 Agent。单次补全本身没有循环，也没有工具。

官方的文本生成说明把这个过程写成：用提示词请模型产生文本。文本可以是散文、代码或 JSON。输出位于响应的指定字段里，而且不能假定文字永远落在同一个下标。学习这一页时，先记住输入和输出的角色，字段路径留到 [大模型 API 调用](/fundamentals/llm-api.md)。

## 最小示例

下面的函数不是模型。它只固定「最后一条用户消息进去，一段带标记的文本出来」，方便看清调用形状。不需要密钥，也不访问网络。

```python
def complete(messages: list[dict[str, str]]) -> str:
    """用规则表示一次补全，方便看清输入和输出。"""
    user_text = ""
    for message in reversed(messages):
        if message["role"] == "user":
            user_text = message["content"]
            break
    return f"补全：{user_text}"


messages = [
    {"role": "user", "content": "什么是补全"},
]
print(complete(messages))
```

`complete(messages)` 得到 `补全：什么是补全`。真实模型会写成新的句子，而且整份消息列表都会被送去，不只是最后一条。替换 `complete` 的实现时，调用方仍然处理「消息列表」和「一段文本」。

## 常见问题

**认为模型已经读过项目文件。** 没放进本次请求的文件、变量和网页，模型都看不到。需要资料时，由程序读出来再写进消息。

**把一次补全叫成 Agent。** 补全是一轮生成。Agent 还要有程序控制的动作和停止条件。能一次写完的任务，就停在补全。

**指望同一提示词永远得到同一段字。** 生成可以变化。要稳定的部分，例如城市名必须属于某个集合，用程序检查，不要只靠再问一次。

**把补全理解成模型在你的电脑上执行代码。** 补全是文本。要不要执行、执行哪一段，由应用程序决定。
